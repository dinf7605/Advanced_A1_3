# 02. 구현 — 코드를 생성시킨 과정

> 사용 도구: **Claude Code** (Anthropic) · 2026-08-26
> PRD가 있었기 때문에 "무엇을 만들지" 대신 **"명세대로 만들어라"**로 지시할 수 있었습니다.

---

## 1. 지시 방식 — 기능 단위가 아니라 계약 단위로

"AI 기능 만들어줘"라고 하지 않았습니다. PRD에 **파일별 계약**을 먼저 정해 두고
그것을 지키게 했습니다 (PRD §4.3, §4.4).

```
js/api.js
  callApi(path, payload, {timeoutMs})
    → { ok:true, data, meta } | { ok:false, code }
    ★ 어떤 경우에도 예외를 던지지 않는다 ★
```

이 계약 하나 덕분에 호출하는 쪽에 `try/catch`가 흩어지지 않았습니다.
실패 처리가 **개인의 주의력이 아니라 구조**로 보장됩니다.
(A2-1의 `llm.generate_json`에서 이어온 방식입니다.)

---

## 2. 만든 순서 — 배포가 깨지는 것부터

PRD의 Day 계획대로 **위험이 큰 것부터** 만들었습니다.

| 순서 | 만든 것 | 왜 이 순서인가 |
|:---:|---------|----------------|
| 1 | `.gitignore` | **코드보다 먼저.** 키 파일이 커밋될 창구를 미리 막는다 |
| 2 | 설정 파일 (`requirements.txt`·`vercel.json`·`.python-version`) | 배포가 깨지는 원인 1위가 여기 |
| 3 | `api/` 3종 | 서버가 되는지부터 확인 (그중 `feedback.py`는 나중에 철회 — [03번](03_오류해결_대화.md) 사건 5) |
| 4 | `index.html` + `css/` | 화면 |
| 5 | `js/` 6종 | 동작 |
| 6 | 문서 | 마지막 |

`requirements.txt`에는 **`requests`만** 넣었습니다.
`fastapi`나 `flask`가 들어가면 Vercel이 프레임워크 프리셋으로 전환하면서
**`/api` 파일들이 함수가 되지 않아 전부 404**가 됩니다. PRD §4.5에 적어둔 함정입니다.

## 3. 검증을 코드 작성과 붙여서 했다

"만들었습니다"로 끝내지 않고 **매 단계 측정**하게 했습니다.

### 백엔드 — 순수 함수부터

```
정상 케이스        -> None
정답이 보기 밖     -> 정답이 보기 안에 없음
요약 2개           -> 요약이 3개가 아님
코드블록 벗기기    -> '{"a":1}'
텍스트 블록 추출   -> {"a":1}
```

`validate()`와 `strip_fence()`는 네트워크 없이 검증할 수 있는 함수라
**API를 부르기 전에** 먼저 확인했습니다.

### 프론트 — 브라우저 DOM을 직접 측정

스크린샷을 눈으로 보는 대신 **숫자로** 확인했습니다.

| 확인 | 방법 | 결과 |
|------|------|------|
| 빈 입력 시 요청이 안 나가는가 | `window.fetch`를 감싸서 호출 횟수를 셈 | **0건** |
| 모바일 가로 스크롤 | `scrollWidth - clientWidth` | **0px** |
| iOS 자동 확대 방지 | `getComputedStyle(textarea).fontSize` | **16px** |
| 해설이 미리 보이는가 | 채점 전/후 `.quiz-explain` 개수 | **0개 → 5개** |
| 터치 영역 | 버튼 `getBoundingClientRect().height` | **49px** |

**배운 점** — "잘 되는 것 같다"와 "0px이다"는 다릅니다.
숫자로 재면 나중에 회귀가 생겼을 때 바로 알 수 있습니다.

## 4. AI가 쓴 코드를 그대로 두지 않은 지점

### `innerHTML`을 쓰지 않게 강제

모델 출력을 화면에 그릴 때 `innerHTML`을 쓰면, 응답에 `<script>`가 섞여 들어올 경우
**그대로 실행**됩니다(XSS). `createElement` + `textContent`만 쓰도록 CLAUDE.md에 규칙으로 박았습니다.

### 응답 블록을 `[0]`으로 집지 않게

과정이 준 규격 예시는 `data["content"][0]["text"]`입니다. 그런데 배열의 첫 원소가
항상 텍스트라는 보장이 없습니다.

```python
# 타입을 확인하고 꺼낸다 — 한 줄 길어지는 대신 조용한 KeyError 가 사라진다
text = next((b["text"] for b in data.get("content", []) if b.get("type") == "text"), None)
```

### 예외를 종류별로 나누게

`except Exception: pass`는 오타(`NameError`)까지 삼켜서 디버깅을 불가능하게 만듭니다.
`Timeout` / `RequestException` / `status_code` 분기로 나눴습니다.
(이 분류가 부족했다는 것은 **배포 후에** 드러납니다 → [03번 문서](03_오류해결_대화.md))

## 5. 로컬에서 배포 환경을 흉내 냈다

`vercel dev`는 Node와 Vercel CLI가 필요합니다. 없이도 `/api`까지 테스트하려고
**`dev_server.py`**를 만들었습니다.

```
정적 파일        index.html, css/, js/  →  그대로 서빙
api/summarize.py →  /api/summarize
```

Vercel과 동일하게 **밑줄로 시작하는 파일은 라우트가 되지 않도록** 흉내 냈습니다.
`/api/_shared` → 404를 로컬에서도 확인할 수 있습니다.

> 이 파일은 **로컬 전용**입니다. 배포 환경에서는 Vercel이 `api/*.py`를 각각
> 독립된 함수로 띄우고 이 파일은 쓰지 않습니다.
> "로컬 환경과 배포 환경의 차이"를 눈으로 보기에 좋은 대비입니다.

## 6. 커밋을 기능 단위로 쪼갰다

과제 제출물 2번이 **커밋 이력**을 요구합니다. 한 번에 올리면 "코드가 있다"는 것만
보여줄 뿐 만들어 온 과정을 보여주지 못합니다.

```
chore: .gitignore 추가 — 키 파일을 코드보다 먼저 막는다
chore: 프로젝트 설정 파일 구성
feat:  백엔드 서버리스 함수 3종 구현
feat:  프론트엔드 화면 4개 섹션 + 반응형 구현
feat:  라우팅·AI 호출·퀴즈 채점·기록·다크모드 구현
feat:  로컬 개발 서버 추가 — Vercel 없이 /api 까지 테스트
docs:  README · 서비스 기획서 · PRD 작성
```

커밋 메시지에 **"무엇을"이 아니라 "왜"**를 적었습니다.
`.gitignore` 커밋 메시지가 "키 파일을 코드보다 먼저 막는다"인 이유가 그것입니다.
