## 사건 1 — 개인 API 키가 제3자 서버로 나갈 뻔했다

### 증상

`.env.local`을 아직 만들지도 않았는데 `/api/health`가 이렇게 답했습니다.

```json
{ "has_api_key": true }
```

**키를 넣은 적이 없는데 "있다"고 나왔습니다.**

### 진단

`/api/health`는 `os.environ.get("ANTHROPIC_API_KEY")`를 봅니다.
파일이 없는데 값이 있다면, 출처는 하나뿐입니다 — **셸 환경 변수**.
다른 프로젝트에서 설정해 둔 키가 그대로 남아 있었습니다.

### 왜 위험한가

`dev_server.py`가 그 키를 그대로 써서 요청을 보내면,
**교육용 게이트웨이(`copa.codyssey.kr`)로 내 개인 키가 전송**됩니다.
401이 나서 실패하는 데서 끝나지 않습니다 — **키 값 자체가 남의 서버에 도달**합니다.

실제로 이 상태에서 테스트 요청 1건이 나갔습니다.

### 원인 — `setdefault`의 함정

```python
os.environ.setdefault(key, value)   # ❌ 이미 있으면 덮어쓰지 않는다
```

"파일 값을 넣는다"는 의도였지만, 실제 동작은 **"셸 값이 있으면 그걸 쓴다"**였습니다.

### 수정

```python
MANAGED_KEYS = ("ANTHROPIC_API_KEY", "CLAUDE_MODEL", "COPA_API_URL", ...)

for key in MANAGED_KEYS:
    os.environ.pop(key, None)      # ★ 먼저 비운다 ★
# 그다음 .env.local 값만 넣는다
```

**"어디서 온 키인지 모르는 채로 밖으로 내보내지 않는다"**가 이 함수의 목적이 됐습니다.

### 배운 점

- 환경 변수는 **눈에 보이지 않는 전역 상태**입니다. 파일에 없다고 값이 없는 게 아닙니다.
- `/api/health`를 먼저 만들어 둔 것이 이걸 잡았습니다. **진단 도구가 첫 번째 방어선**이었습니다.

## 사건 2 — 타임아웃 25초가 부족했다

### 증상

로컬에서 잘 되던 AI 기능이, 긴 노트에서는 아슬아슬했습니다.

### 진단 — 추측하지 않고 쟀다

같은 3,950자 노트를 넣고 모델만 바꿔 측정했습니다.

| 모델 | 실제 매핑된 모델 | 응답 시간 | 출력 토큰 |
|------|-----------------|----------|-----------|
| `claude-sonnet-4` | `claude-sonnet-4-6` | **19.2초 / 24.1초** (편차 큼) | 1,255 |
| `claude-haiku-4` | `claude-haiku-4-5-20251001` | **10.5초** | 1,669 |

**24.1초.** 타임아웃 25초를 거의 다 썼습니다. 조금만 느려지면 실패합니다.

### 원인

처음 25초를 잡을 때 **재보지 않고 추정**했습니다.
PRD에 "약 8~15초"라고 써 두었는데, 실제는 그 두 배였습니다.

### 수정 — 사다리를 통째로 밀었다

타임아웃 하나만 올리면 **바깥쪽이 더 짧아져서 순서가 뒤집힙니다.**

```
requests.post(timeout=40) × (파싱 실패 재호출 1회)  ≈ 최악 80초
프론트 AbortController                                90초
Vercel maxDuration                                   100초
```

**왜 순서가 중요한가** — 프론트가 먼저 끊으면, 서버는 **아무도 안 받는 곳으로**
성공 응답을 보냅니다. 사용자는 실패로 보는데 **쿼터는 소모됩니다.**

그리고 **기본 모델을 `claude-haiku-4`로 바꿨습니다.** 2배 빠르고 의미 검증도 통과했습니다.
모델을 상수가 아니라 **환경 변수**로 빼 둔 덕분에 코드는 한 줄도 고치지 않았습니다.

### 배운 점

- **"약 ~초"라고 쓴 숫자는 전부 추측입니다.** 재기 전에는 설계 근거가 될 수 없습니다.
- 타임아웃은 하나가 아니라 **여러 층**입니다. 한 층만 고치면 순서가 깨집니다.

## 사건 3 ⭐ — 배포에서만 터졌다: 빈 문자열 환경 변수

**로컬에서는 완벽했고, 배포에서만 실패했습니다.** 이 과제가 확인하려는 상황 그 자체입니다.

### 증상

```
POST /api/summarize
→ 504  {"ok": false, "code": "UPSTREAM_TIMEOUT"}     0.3초
```

### 첫 번째 단서 — 숫자가 이상하다

**0.3초짜리 타임아웃은 존재하지 않습니다.** 타임아웃은 40초로 잡혀 있습니다.
즉 **오류 코드가 거짓말을 하고 있었습니다.**

### 진단 — `/api/health`를 열었다

```json
{
  "has_api_key": true,
  "model": "",                 ← ★ 빈 문자열 ★
  "custom_api_url": true       ← ★ 기본값이 아니다 ★
}
```

`model`이 빈 문자열이고, `custom_api_url`이 `true`.
**Vercel 환경 변수에 이름만 만들고 값을 비워 둔 상태**였습니다.

### 원인 — `.get(키, 기본값)`은 생각과 다르게 동작한다

```python
os.environ.get("COPA_API_URL", "https://copa.codyssey.kr/v1/messages")
```

이 코드는 **키가 "없을 때만"** 기본값을 씁니다.
Vercel 대시보드에서 변수 이름만 만들고 값을 비우면, 키는
**"없는" 것이 아니라 "빈 문자열로 존재"**합니다.

→ `""`가 그대로 흘러 들어가 `requests.post("")`가 호출됐고,
`MissingSchema` 예외가 나면서 **0.3초 만에** 실패했습니다.

### 왜 "타임아웃"으로 보고됐나 — 내 두 번째 실수

```python
except requests.exceptions.RequestException:
    return None, "UPSTREAM_TIMEOUT"
```

`MissingSchema`는 `RequestException`의 **하위 클래스**입니다.
그래서 **설정 오류가 네트워크 타임아웃으로 뭉뚱그려졌습니다.**
로그를 봐도 원인을 알 수 없는 상태였습니다.

### 수정 — 두 군데

**① 빈 문자열도 기본값으로 떨어지게**

```python
os.environ.get("COPA_API_URL", 기본값)     # ❌
os.environ.get("COPA_API_URL") or 기본값   # ✅
```

**② 설정 오류를 네트워크 오류와 분리**

```python
except (requests.exceptions.MissingSchema,
        requests.exceptions.InvalidURL,
        requests.exceptions.InvalidSchema):
    # 네트워크 문제가 아니라 "설정이 틀렸다"
    print("[summarize] COPA_API_URL 이 비었거나 형식이 잘못됐다 — 환경 변수 확인")
    return None, "BAD_CONFIG"
```

수정 후 push → Vercel 자동 재배포 → `/api/health`가 정상값을 반환:

```json
{ "model": "claude-haiku-4", "custom_api_url": false }
```

→ AI 기능 **9.0초**에 정상 동작 확인.

### 배운 점 (이 과제의 핵심)

1. **오류 메시지를 믿지 말고 숫자를 보라.** "0.3초 타임아웃"이 첫 단서였습니다.
2. **예외 클래스 계층을 알아야 한다.** `MissingSchema ⊂ RequestException`을 몰랐으면
   계속 네트워크 문제를 찾았을 것입니다.
3. **진단 엔드포인트를 먼저 만들어 두면 원인이 1분 만에 나온다.**
   `/api/health`를 Day 2에 만든 이유가 정확히 이것이었고, 실제로 값을 했습니다.
4. **로컬과 배포는 다르다.** 로컬 `.env`에는 빈 변수가 없었고, Vercel 대시보드에만
   있었습니다. **로컬에서 재현되지 않는 버그**가 존재합니다.

## 사건 4 — AI의 지적이 틀렸던 경우

내가 `claude-sonnet-4` / `claude-haiku-4`를 쓰겠다고 하자
AI가 **"두 ID 모두 존재하지 않는다"**며 다른 모델을 제안했습니다.

하지만 나는 **교육용 게이트웨이**를 쓸 예정이었고, 거기서는 그 ID가 동작합니다.
규격을 제시하자 AI가 설계를 다시 맞췄습니다.

### 그런데 AI의 지적이 완전히 헛되지도 않았다

나중에 실호출로 확인해 보니, 게이트웨이가 **별칭을 실제 모델로 매핑**하고 있었습니다.

```
보낸 값: claude-sonnet-4   →  응답의 model: claude-sonnet-4-6
보낸 값: claude-haiku-4    →  응답의 model: claude-haiku-4-5-20251001
```

**응답의 `model` 필드가 우리가 보낸 값과 다릅니다.** 로그를 볼 때 헷갈릴 지점이라
`CLAUDE.md`에 기록해 두었습니다.

### 배운 점

- AI가 지적한다고 무조건 맞지 않습니다. **내가 쓰는 환경의 정보는 내가 더 잘 압니다.**
- 다만 지적을 무시하지 말고 **실측으로 확인**하면, 그 과정에서 몰랐던 사실이 나옵니다.

## 진단 절차 정리 — 증상별로 볼 곳이 정해져 있다

이 네 사건을 겪고 나서 정리한 것입니다. README와 CLAUDE.md에도 넣었습니다.

```
/api/... 가 404  →  ① 파일명·경로 (api/summarize.py → /api/summarize)
                    ② requirements.txt 에 프레임워크가 들어갔는가
                    ③ 클래스 이름이 소문자 handler 인가

/api/... 가 500  →  /api/health 를 브라우저에서 연다
                    has_api_key: false  → 환경 변수 미설정 또는 재배포 누락
                    model: ""           → 변수가 "빈 값"으로 등록돼 있다   ← 사건 3
                    custom_api_url:true → COPA_API_URL 이 비었거나 잘못됐다
                    true 인데 500       → Vercel Runtime Logs 확인

응답이 너무 빠르게 실패  →  타임아웃이 아니다. 설정 오류를 의심하라   ← 사건 3

로컬은 되는데 배포만    →  환경 변수 / 패키지 / 파일명 대소문자
                          (Vercel은 Linux — Windows와 달리 대소문자를 구분)

CSS·JS가 옛날 것        →  강력 새로고침 (Ctrl+Shift+R)
```
