# 01. 기획 — 아이디어와 설계를 정하는 과정

> 사용 도구: **Claude Code** (Anthropic) · 2026-08-26
> 이 문서는 "AI에게 무엇을 시켰고, 무엇을 **내가 결정했는지**"를 남긴 기록입니다.

---

## 1. 시작점 — AI에게 아이디어를 통째로 맡기지 않았다

첫 지시는 이랬습니다.

> "이걸 작업하게 CLAUDE.md 만들어주고 PRD 작성해줘" (+ 과제 명세 전문 첨부)

AI가 바로 문서를 쓰지 않고 **세 가지를 되물었습니다.**

| 물어본 것 | 왜 물었는가 | 내 결정 |
|-----------|-------------|---------|
| 어떤 서비스를 만들 것인가 | 페이지 구성·AI 기능 명세가 전부 여기서 갈림 | **학습노트 요약·퀴즈 생성기** |
| AI API는 무엇을 쓸 것인가 | 인증 헤더·응답 파싱 코드가 전부 달라짐 | **Claude API** |
| 보너스를 어디까지 넣을 것인가 | 작업량과 일정이 달라짐 | 다크 모드 + 결과 저장/알림 **둘 다** |

**배운 점** — 이 세 가지는 AI가 대신 정할 수 없는 것들입니다. 정해주지 않으면
AI는 "그럴듯한 아무 서비스"를 만들고, 나중에 바꾸려면 문서와 코드를 전부 고쳐야 합니다.
**갈림길을 먼저 닫는 것**이 기획의 실체였습니다.

---

## 2. 서비스 정의 — 왜 "요약"이 아니라 "요약 + 퀴즈"인가

처음 떠올린 것은 "노트 요약기"였습니다. 그런데 그건 이미 널려 있고,
과제 제약에도 **"템플릿/예시를 그대로 복제하지 않는다"**가 있습니다.

그래서 **문제 정의를 다시 했습니다.**

| 문제 | 요약만으로 풀리는가 |
|------|---------------------|
| 필기해 놓고 다시 안 본다 (어디부터 볼지 모름) | ✅ 풀린다 |
| 다시 읽어도 기억에 안 남는다 | ❌ **안 풀린다** — 읽기는 인출이 아니다 |

두 번째 문제 때문에 **퀴즈 생성**이 들어갔습니다.
스스로 낸 문제는 이미 답을 알기 때문에 인출 연습이 되지 않습니다.
**제3자 시점의 문제**가 필요하고, 그게 AI가 대신할 수 있는 일이었습니다.

서비스명 **"되새김"**도 여기서 나왔습니다 — 되새김질(반추) = 한 번 삼킨 것을
다시 꺼내 씹는다는 학습법의 은유입니다. 기능명이 아니라 **개념의 이름**입니다.

## 3. 확정한 설계 결정과 근거

AI가 대안을 표로 제시하면 내가 고르는 방식으로 진행했습니다.

### 페이지를 나눌 것인가, 섹션으로 둘 것인가

| 안 | 문제 |
|----|------|
| `study.html`·`history.html` 등 파일 분리 | 헤더·네비·테마 스크립트를 4개 파일에 **복제**. 메뉴 하나 고치려면 4곳을 고침 |
| **단일 `index.html` + 해시 라우팅** | ✅ 채택. 네비 활성화 처리가 **JS의 역할을 보여주는 실습**이 됨 |

### O/X 문항도 `options`를 갖게 할 것인가

"O/X는 보기가 필요 없으니 빼자"가 자연스러워 보였지만, 그러면 스키마에 분기가 생기고
렌더링·채점 코드도 갈라집니다. **`options: ["O","X"]`로 통일**해서
코드 하나로 끝나게 했습니다. *일부러 정규화하지 않은* 결정입니다.

### 기록을 서버에 저장할 것인가

이 서비스에는 **로그인이 없습니다.** 로그인 없이 서버에 저장하면 누구의 기록인지
구분할 수 없고, 남의 노트를 볼 수 있는 구조가 됩니다.
→ **localStorage**로 결정. "저장은 하되 서버에 두지 않는다."

## 4. AI가 문서를 쓰기 전에 사실을 확인하게 했다

PRD를 쓰려면 Vercel과 Claude API의 **정확한 사양**이 필요합니다.
AI가 기억으로 쓰지 않고 **공식 문서를 직접 확인**하도록 했고, 그 결과가 PRD §1.2가 됐습니다.

확인된 것 중 설계를 바꾼 것들:

- `/api` 함수 진입점은 **소문자 `handler`** (대문자면 404)
- **프레임워크 프리셋이 감지되면 `/api` 파일이 함수가 되지 않는다**
  → `requirements.txt`에 `fastapi`/`flask`를 절대 넣지 않기로 확정
- `_`로 시작하는 파일은 라우트가 되지 않는다 → `_shared.py`를 공용 모듈로 쓸 수 있음
- Python은 `maxDuration`을 **`vercel.json`에서만** 설정 가능

**배운 점** — "AI가 아는 것"과 "지금 실제로 그런 것"은 다릅니다.
배포가 깨지는 항목일수록 문서로 확인해야 합니다.

## 5. 모델 선택에서 한 번 부딪혔다

내가 `claude-sonnet-4` / `claude-haiku-4`를 쓰겠다고 했을 때,
AI가 **"두 ID 모두 현재 표준 API에 존재하지 않는다"**며 다른 것을 제안했습니다.

그런데 나는 **과정에서 제공한 교육용 게이트웨이**를 쓸 예정이었고,
거기서는 그 ID가 실제로 동작합니다. 규격을 보여주자 AI가 설계를 다시 맞췄습니다.

**배운 점** — AI의 지적이 항상 맞지는 않습니다. **내가 쓰는 환경의 정보**는
내가 더 잘 압니다. 다만 AI가 "없는 ID"라고 짚어준 덕분에
**게이트웨이가 별칭을 실제 모델로 매핑한다**는 사실을 나중에 실측으로 확인하게 됐습니다
(`claude-sonnet-4` → `claude-sonnet-4-6`).

## 6. 요구사항 누락 점검 — 문서를 다시 감사시켰다

PRD 초안이 나온 뒤 **"요구사항이 다 들어갔는지 점검해줘"**라고 시켰습니다.
기능 요구사항은 전부 있었지만, **과제 §7 제약 사항이 통째로 빠져 있었습니다.**

찾아낸 구멍 9개 중 중요한 것:

| 구멍 | 왜 문제인가 |
|------|-------------|
| 제약 사항 추적표 없음 | 프레임워크 금지·키 관리·재현 가능성이 체크리스트에 없었다 |
| "템플릿 복제 금지"에 대한 답 없음 | 명시적 금지 항목인데 근거를 준비하지 않았다 |
| **AI 도구 로그를 마지막 날 만들게 되어 있었음** | **대화 로그는 나중에 복원할 수 없다** |
| 키 유출 시 이력 정리 절차가 한 줄뿐 | "정리할 수 있어야 한다"는 요구를 못 만족 |

**세 번째가 가장 위험했습니다.** Day 7에 "로그 정리"만 있고 Day 2~6에 저장 항목이
없었습니다. 특히 이 03번 문서(오류 해결)는 **오류가 난 그 순간에만 존재**합니다.
→ Day 1~6 각 날짜에 📝 저장 체크박스를 넣었습니다.

**배운 점** — 문서를 쓰는 것과 **문서가 요건을 다 덮는지 확인하는 것**은 별개의 작업입니다.
